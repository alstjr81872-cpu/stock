# 대화형 기획과 집필

Cloudflare/Supabase 운영 화면의 중심은 작품별 채팅입니다. 파일이나 상세 기획 모듈 없이 시작할 수 있습니다.

1. **새 작품**에서 장르나 원하는 장면을 적고 **대화 시작하기**를 누릅니다. 파일은 선택입니다. 대화창의 첫 메시지를 보내면 AI가 질문과 대안을 제시합니다.
2. 탐색할 때는 한 번에 핵심 질문 1~3개를 합니다. ‘그 설정 좋아’, ‘이 이름으로 가자’처럼 채택하거나 직접 정한 내용은 설정집에 저장합니다. ‘나머지는 알아서 기획해줘’라고 하면 추가 질문 대신 필요한 결정을 내려 기획안을 만듭니다.
3. 설정집은 인물·세계관·서사·장르·문체·표현 범위로 나눕니다. 수정하거나 보관할 수 있고, 보관한 항목은 이후 생성 입력에서 제외합니다. 변경 전후와 현재 사용자 발언의 저장 근거를 이력으로 보존합니다.
4. 준비되면 **이 기획으로 시놉시스 만들기**로 이동합니다. 기존 10화 단위 시놉시스, 회차 분량, 복선 투척·회수 장부를 사용합니다. [연재 안내](serial-synopsis.md).
5. 집필실에도 **집필 어시스턴트**가 있습니다. ‘이 도입이 루즈해. 실제로 고쳐줘’, ‘독백을 더 뻔뻔하게’, ‘이 설정을 유지하고 대사를 보완해줘’처럼 요청하세요. 현재 회차의 저장된 원고를 읽고 구체적인 수정안을 만듭니다.
6. **원고 수정안 비교 → 수정안을 원고에 적용**으로 변경합니다. 적용 전 원고를 버전으로 보관합니다. 한 번에 1~3개 구간을 고치며 큰 개작은 순서대로 나눕니다. 적용은 원고 전체 자동 확정이 아니므로 독립 검토가 다시 필요합니다.

대화의 문체 변경은 설정집에 기록해 이후 집필과 수정에도 전달합니다. 이전 기획과 충돌하면 최신 대화 설정을 우선하도록 모델에 지시합니다. 이미 작성한 문장은 작가가 수정안을 적용할 때 바뀝니다. 확정 원고는 기존 ‘새 초안으로 편집’ 흐름을 사용해야 하며, 원고/설정/회차가 바뀐 뒤 오래된 제안을 적용할 수 없습니다.

처음 기획을 활성화할 때는 기존 내부 기획 저장 형식을 활용하지만 화면에서 파일 분석·인터뷰·모듈 작성을 강제하지 않습니다. 이미 시놉시스나 원고가 있는 작품의 대화는 설정·문체를 개선하는 데 사용하며, 새 기획을 첫 회차부터 시작하려면 새 작품을 만드세요. 기존 작품과 원고를 삭제하지 않습니다.

## 참고 원고와 문체

대화창에서 파일 종류를 **문체 참고 원고**로 선택해 TXT·MD·DOCX·PDF를 첨부할 수 있습니다. 분석만 요청하거나, ‘분석해서 이 작품에 적용해줘’라고 요청할 수 있습니다. 최근 첨부 3개에서 각각 앞 12,000자를 전달하며 잘린 자료는 모델에도 표시합니다. 원본은 보관합니다. 파일은 8MB 이하, 추출된 본문 40,000자 이하, 작품당 10개입니다.

기본 집필 지침은 작가가 제공한 참고 원고의 강한 내면, 대사와 반응의 교차, 문장 길이 변화, 구체적인 증거에 의한 반전에서 추출했습니다. 작품 고유 문장·인물·사건을 기본 지침에 넣지 않습니다. 설명·준비 동작의 반복을 줄이고 주인공의 선택과 상대의 반응을 앞당깁니다. 작가가 대화로 바꾼 문체가 기본 지침보다 우선합니다.

## 저장과 비용

대화와 설정집은 계정별 서버에 저장합니다. 대화는 20개 턴씩 불러오며 ‘이전 대화 더 보기’로 오래된 기록을 확인할 수 있습니다. 모델에는 최근 12개 턴, 누적 요약, 확정 설정집, 현재 기획과 관련 회차를 전달합니다. 오래된 모든 대화를 매번 전송하지 않습니다. 요약에는 아직 탐색 중인 제안을 확정 사실과 구분하도록 지시합니다.

기본은 응답마다 비용 확인입니다. **대화 비용 · 전송 설정**에서 응답당 한도를 정하고 유료 전송에 동의하면 현재 화면에서만 그 한도 내 자동 전송이 가능합니다. 사전 계산과 서버 월 예산·모델 제한은 매번 검사합니다. 자동 유료 재시도는 하지 않으며 실패 시 입력 메시지를 보존합니다. 모델 응답 후 저장 충돌이 나면 응답은 작업 기록에 남을 수 있으므로 재요청 전에 확인하세요.

기획 대화는 기획 역할 모델, 집필 대화는 편집 역할 모델을 사용합니다. 모든 실제 원고 생성은 집필 역할 모델을 사용합니다. 새 SQL, 키, 별도 유료 서버는 필요하지 않습니다.

앱은 성인 장르라는 이유만으로 별도의 요청 차단·순화 필터를 적용하지 않습니다. 선택한 모델/제공자의 정책이나 응답 제한은 앱에서 해제할 수 없습니다. 성인 관계의 나이와 동의·경계를 명확하게 설정하세요.

설정 채택 의도와 원고 품질은 모델이 해석합니다. 자동 저장이 의미적 정확성을 보장하지 않으므로 채팅의 ‘설정집에 저장’ 표시와 실제 설정집 내용을 확인하고 고칠 수 있습니다. 자동 테스트는 저장·연결·충돌 차단 동작을 검증하며 실제 모델의 문장 품질을 대신하지 않습니다.
