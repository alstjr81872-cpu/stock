# STEP 3 자동 전개

스토리 설계에서 첫 회차 플롯을 만든 뒤 **자동 전개**를 누릅니다. 승인 전 플롯에서 사용할 수 있습니다.

1. **누락·모호함 점검**: 행동 이유, 장면 사이 시간·장소·인과, 관계 변화, 현재 장면에 필요한 세계 규칙, 독자 보상 등을 확인합니다. 기존 미정뿐 아니라 빠뜨린 항목도 최대 12개 발견합니다. 이 단계는 플롯을 바꾸지 않습니다.
2. **설정·장면 구체화**: 점검 결과와 기존 미정·위험을 함께 처리합니다. 필요한 설정을 구체화하고 장면의 목표·행동·결과에 반영합니다. 지금 필요하지 않은 장기 설정은 이후 전개 메모로 연결합니다.
3. 제안의 결정 근거·다듬은 장면·남은 문제를 확인하고 **이 전개 반영**을 누릅니다. 반영 뒤에도 검토 대기 상태이며, 플롯을 직접 승인해야 집필할 수 있습니다.

두 단계는 각각 작업량에 맞는 비용을 미리 계산하고 동의를 받습니다. 2단계 비용 확인을 취소하면 점검 결과 창의 **점검 결과로 전개 계속**으로 이어갈 수 있습니다. 실패한 유료 요청을 자동 반복하지 않습니다.

현재 회차의 필수 누락을 해결하지 않고 장기 메모로 넘기는 것은 차단합니다. 해결할 수 없는 부분은 확인할 문제로 남겨 플롯 승인 전에 보여줍니다. 모델이 모든 모호함을 찾아내거나 항상 타당한 설정을 만들 것을 보장하지는 않으므로 반영 전 장면을 검토하세요.

원문·기획 트리·기존 원고는 자동 변경하지 않습니다. 기존 장면 ID와 과거 장기 메모를 보존합니다. 반영 전 플롯과 결정 근거는 `plot_history`에 저장하며 점검·제안·이력은 프로젝트 내보내기에 포함됩니다. 이후 전개 메모는 집필 프롬프트에도 전달합니다.

API는 `/plot/develop/check` → `/plot/develop`(auditId 포함) → `/plot/develop/apply` 순서입니다. 각 기록은 프로젝트/계정에 귀속되고 revision CAS로 오래된 점검·중복 반영을 차단합니다. 기존 `/plot/develop`의 점검 ID 없는 요청도 미정·위험 정리에 사용할 수 있습니다. 새 SQL이나 비밀 키 설정은 필요 없습니다.

Cloudflare/Supabase 경로에서 제공하며, Firebase 개발 경로의 기존 플롯 편집은 보존합니다. 실제 모델 품질과 운영 배포 검수는 테스트 응답을 이용한 자동 검증과 별개입니다.
