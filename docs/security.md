# 데이터 소유권 및 변경 권한

| 데이터 | 읽기 | 브라우저 SDK 쓰기 | 서버 쓰기 |
|---|---|---|---|
| `/users/{uid}/projects/{id}`와 바로 아래 세부 문서 | 본인 | 금지 | 검증 토큰 UID 경로 + revision CAS |
| `/users/{uid}/style_profiles/{id}` 및 버전 | 본인 | 금지 | 검증 UID, 승인 전용 엔드포인트 |
| `/users/{uid}/jobs`, `/usage` | 본인 | 금지 | 예약/완료 서버 트랜잭션 |
| 승인·캐논·확정 원고 | 본인 | 금지 | 상태와 입력 버전 검사 |
| Storage `/users/{uid}/...` | 본인 | 금지 | 검증 업로드 또는 UUID 불변 버전 |
| 기타 모든 경로 | 금지 | 금지 | 별도 운영 기능 없음 |

클라이언트 개인 초안 직접 쓰기도 초기 버전에서는 허용하지 않습니다. 모든 변경을 서버 경유로 제한해 문서 필드별 허용 실수와 승인 우회를 줄입니다. Admin SDK는 Rules를 우회하므로 서버 API도 UID 경로를 강제합니다. 다른 UID를 받는 매개변수가 없고, 공개 ID로 다른 계정 자료를 조회하면 자신의 경로에서 찾지 못해 404입니다.

원문/참고 자료는 외부 모델 입력으로만 취급합니다. 비밀 키를 모델 문맥에 넣지 않으며 upstream 오류 본문을 사용자에게 그대로 반환하지 않습니다. 예측 불가 모델 결과는 스키마 검증 후 CAS로 적용합니다. Firestore 트랜잭션 콜백에서 모델 요청이나 Storage 객체 쓰기를 하지 않습니다.

브라우저에는 로그인 토큰만 탭 세션 지속성을 사용하며 원고 LocalStorage/IndexedDB 영구 캐시는 두지 않습니다. 로그아웃은 Auth 세션과 React의 계정 데이터 상태를 지웁니다. 편집 저장 실패·충돌은 완료로 표시하지 않고 페이지 이동 전에 저장을 시도합니다. 확정 원고를 수동 수정하면 새 초안과 무효화된 플롯 상태가 됩니다.

문서 본문 필드는 인덱싱에서 제외합니다. 현재 본문이 UTF-8 650KB를 초과하면 Storage로 분기합니다. 일반 문서 전체 크기는 보수적 JSON 850KB 기준으로 차단합니다. 추후 더 큰 기획을 지원하려면 모듈별 문서 분리와 로드 전략을 확장해야 합니다. 현재 기획서 섹션은 프로젝트 문서 안에 있고 별도 승인 스냅샷은 Storage에 있습니다.

Archive와 큰 본문은 객체 저장 → STAGED 진단 메타 → Firestore CAS → COMMITTED 순서입니다. 분산 트랜잭션이 아니므로 커밋 실패 객체를 자동 제거하지 않습니다. 재해 복구 운영, 데이터 영구 삭제·계정 삭제, worker IAM, RAG 누출 방지 검증은 아직 구현·검증이 필요한 기능입니다.
