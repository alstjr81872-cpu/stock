# 구현·검증 현황

## 대화형 기획·설정집·집필 어시스턴트 (2026-10-20)

- 운영 기획 화면을 작품별 채팅과 설정집으로 교체했습니다. 파일 없이 장르 한 줄로 시작하고 AI가 질문하며 구체화합니다. 명시적으로 위임하면 질문 대신 완성된 기획과 설정을 제안·저장하도록 구성했습니다.
- 채택·직접 지정·위임한 설정을 현재 발언의 근거와 함께 저장합니다. 설정집 수정·보관과 변경 이력을 지원하며 시놉시스·플롯·집필·검토·수정 입력으로 연결합니다. 대화는 20턴 단위로 불러오고 200턴 이상도 이어서 조회합니다. 모델 입력에는 최근 12턴과 요약·설정집을 사용합니다.
- 집필 대화는 저장된 현재 원고를 읽고 1~3개 구간의 실제 수정안을 제안합니다. 원문 위치/중복/겹침을 검증하고 비교 후 명시 적용합니다. 원고·설정·회차·연재 버전 변경 시 오래된 적용을 차단하며 적용 전 원고를 보관하고 검토를 무효화합니다. 설정 변경 후에는 독립 검토도 다시 필요합니다.
- 참고 원고에서 추출한 목소리·대사/내면 전환·속도·구체적 반전 지침을 생성·검토·수정에 전달합니다. 별도 앱 성인 장르 차단은 없으며 모델/제공자의 제한은 유지합니다. 기본은 응답별 비용 확인이고 선택적으로 현재 화면에서 응답당 한도 내 전송에 동의할 수 있습니다.
- 서버 테스트 **60개**를 통과했습니다. 파일 없는 시작·대화 이어가기·설정 저장·기획 위임·참고 파일·원고 수정 비교/적용·이전 버전 보관·동시 편집 충돌과 오래된 제안 차단을 검증했습니다. 브라우저는 테스트 API/인증/모델 응답으로 기획 채팅·설정 편집·집필 대화·수정안 적용과 320~1440px 화면을 검사합니다. [사용 방법](conversational-writing.md). 실제 OpenRouter의 대화 의도 해석, 문체와 재미는 실제 작품에서 추가 검수가 필요합니다. 새 SQL·키·서비스 설정은 없습니다. 아래 항목은 이전 흐름의 개발 이력입니다.

## 파일에서 바로 연재: 간결한 기획·복선 장부 (2026-10-20)

- 운영 화면을 `파일 · 기획안 → 10화 시놉시스 → 집필`의 세 단계로 재구성했습니다. TXT·MD·DOCX·PDF에서 짧은 기획, 인물, 장르, 문체를 추출하고 편집·확인 뒤 첫 시놉시스로 바로 이동합니다. 모듈/트리 작성과 별도 인터뷰를 필수 단계에서 제거했습니다.
- 기획과 생성 지침을 초반 사건·주인공의 선택·개성 있는 반응·회차별 보상 중심으로 수정했습니다. 장면 길이를 균등하게 늘리던 처리를 바꿔 짧은 도입과 긴 충돌/보상의 상대적 비중을 유지합니다. 실제 생성 분량과 재미를 보장하는 규칙은 아닙니다.
- 복선의 고정 ID, 투척/회수 회차와 방법을 장부에 저장합니다. 다음 구간의 예정된 회수 누락, 일정의 임의 변경, 장면 연결 누락을 차단합니다. 실제 원고의 투척·회수를 사람이 확인한 뒤 확정해야 장부 상태가 변경됩니다. 설정 사실도 도입 회차와 함께 누적하며 미래 설정·회수 답을 이전 회차에 미리 노출하지 않도록 입력을 제한합니다.
- 기획 재적용은 새 연재 버전으로 분리합니다. 기존 기획 전체, 원고, 회차별 플롯, 시놉시스를 보관하고 이전 버전/다른 회차 탭의 원고 저장을 차단합니다.
- 서버 테스트 **54개** 통과. 파일 업로드부터 새 기획 적용, 1~10화 기록, 집필, 9화 투척→17화 회수, 11~20화 누락 차단, 원고 확인·장부 갱신, 새 연재 버전 격리까지 검증했습니다. 브라우저에서 세 단계 이동·편집·유료 호출 동의·다음 구간 안내·원고의 회수 확인과 320~1440px 화면을 검증했습니다. 인증/API/모델 응답은 테스트용이며 실제 OpenRouter 문장 품질과 공개 배포는 별도 확인이 필요합니다.
- [사용 방법](fast-story-workflow.md). 추가 SQL·키·유료 서비스 설정은 없습니다. 아래 항목은 이전 기능과 개발 이력입니다.

## 자동 전개: 누락 점검과 단계별 구체화 (2026-10-20)

- STEP 3에 자동 전개를 추가했습니다. 원래 표시된 미정·위험뿐 아니라 인물의 동기, 장면 전환, 필요한 설정과 독자 보상의 누락·모호함을 먼저 점검하고, 저장한 점검을 바탕으로 구체화합니다. 단계마다 비용 확인을 거치며 유료 실패를 자동 반복하지 않습니다.
- 결정 근거와 장면을 미리 보고 명시 적용합니다. 현재 회차에 필요한 누락의 무근거 이월을 막고, 해결할 수 없는 항목은 확인할 문제로 보존합니다. 장기 결정은 승인 차단 항목과 분리된 이후 전개 메모로 남겨 집필 입력에도 전달합니다.
- 기존 장면 ID·원문·기획 트리·원고를 보존하며, 이전 플롯/결정 이력/점검 기록을 내보내기에 추가했습니다. 중복/오래된 적용, 문제의 조용한 삭제, 장면 수정 없는 해결 선언을 차단합니다. 서버 테스트 45개 통과. 실제 모델 품질과 운영 배포 확인은 별도입니다.

## 작업별 비용 사전 계산과 예약 정산 (2026-10-19)

- Cloudflare의 모든 AI 작업에 사전 계산 요청을 추가했습니다. 모델·실제 입력·작업량·남은 월 예산으로 비용 상한을 계산한 뒤 확인창에 자동 입력합니다. 기존 일률적인 $0.15 기본 상한에 묶이지 않으며 사용자가 확인한 한도 내에서만 유료 요청을 실행합니다.
- 사전 계산은 Supabase 읽기와 공개 모델 카탈로그 조회만 하며 유료 생성·작업 생성·예산 예약을 하지 않습니다. `X-NF-Preflight` 요청도 동일한 인증·소유권·단계·revision 검증을 거칩니다. 계산 이후 변경된 가격/예산/문서 조건은 실행 시 다시 검사합니다.
- 과도했던 최소 출력 공간을 줄이고 자동 기획에서 현재 모듈의 중복 입력을 제거했습니다. 긴 응답의 권장 공간과 요청/모델/월 예산의 실제 제한은 유지합니다.
- 실제 비용은 응답 형식 검증 전에 읽습니다. 잘리거나 형식이 잘못된 응답도 알려진 실제 금액으로 원자 정산합니다. 결제/인증 등 명확한 거절은 0으로 정산하고, 동시 정산은 revision CAS로 한 번만 반영합니다. 실제 과금 여부를 모르는 타임아웃은 계속 보수적으로 예약을 유지합니다. 과거 금액을 확인할 수 없는 예약을 임의로 삭제하지 않습니다.
- 월 예산이나 실제 OpenRouter 잔액을 임의로 올리지 않습니다. 실제 한도가 소진된 경우에는 여전히 차단하고 앱 예산과 OpenRouter 잔액의 차이를 안내합니다. 자동 유료 재시도는 없습니다.
- SQL/API/Workers 엔진/예산 계산 테스트 28개 통과. 브라우저에서 자동 견적 표시, 동의 전 유료 호출 없음, 확인한 비용 상한으로 1회 실행을 확인했습니다. 테스트 제공자 응답을 사용했습니다.

## 미정·충돌 자동 기획 (2026-10-19)

- Cloudflare 기획서 모듈의 미정/설정 충돌 옆과 모듈 상단에 자동 기획 버튼을 추가했습니다. 저장 전 편집 내용을 포함해 원문 요구·인터뷰·기존 기획을 바탕으로 해결안과 이름/신분/배경을 제안합니다.
- 결정 근거, 이름/배경, 관련 모듈의 수정 전후를 미리 보고 적용합니다. 적용은 단일 원자 커밋으로 관련 모듈·인물 이름·결정 기록을 함께 저장하고 변경 전 기획 이력을 남깁니다. 원문 요구와 원본 파일은 보존합니다.
- 이후 모듈·플롯·집필·독립 검토 입력에 적용된 결정을 전달합니다. 관련 검토와 기존 플롯 승인은 무효화되어 최신 기획 기준의 검수가 필요합니다. 기획/원고를 자동 승인하지 않습니다.
- 원문 근거 삭제, 결정 근거 없는 미정/충돌 제거, 잘못된 이름 매핑, 오래된/이미 적용한 제안의 덮어쓰기를 차단합니다. 해결 불가능한 충돌은 미해결 항목으로 유지합니다.
- SQL/API/실행 엔진/자동 기획 테스트 24개 통과. 브라우저에서 옆 버튼 → 미저장 내용 전송 → 이름/기획 미리보기 → 명시 적용 → 모바일 화면을 테스트했습니다. 인증/모델/API 응답은 테스트용이며 실제 생성 품질 검증은 아닙니다.
- 새 SQL이나 키 설정은 필요하지 않습니다. 기존 planning 역할 모델과 요청 예산을 사용합니다. Firebase/Python 개발 경로에는 이 API를 추가하지 않았습니다.

## 자동 토큰 배분 (2026-10-19)

- Cloudflare 배포 경로의 고정 3,000 출력 토큰 설정과 수동 입력 UI를 제거했습니다. 기존 저장값도 무시하므로 설정을 다시 저장할 필요가 없습니다. 기존 Firebase/Python 개발 어댑터는 별도 보존 경로입니다.
- 작업 종류, 입력량, 원고 목표 길이, 카탈로그의 모델 출력·문맥 한도, 요청/남은 월 예산으로 응답 공간을 자동 계산합니다. 최소 응답 공간을 확보할 수 없으면 유료 호출 전에 알립니다. 최대 공간은 실제 출력량/비용과 다릅니다.
- 지원 모델에만 낮은 추론 노력 옵션을 전달합니다. 작업 기록에 자동 계산한 응답 공간을 남기며 잘린 응답의 자동 유료 재호출은 하지 않습니다.
- JSON Schema의 불필요한 제목/기본값 메타데이터와 반복 전송되는 처리 기록을 줄입니다. 원문 분석은 전체 원문을 보존하고 중복 요구 텍스트를 ID/원문 위치로 참조합니다. 실제 요구·바이블·문체 규칙은 유지합니다.
- SQL/API/실행 엔진/모델 오류/자동 배분 테스트 21개 통과. 테스트 모델 응답을 사용했으며 실제 OpenRouter 품질·절감률이나 모든 모델의 무중단 출력을 보장하지 않습니다.

## 모델 요청 실패 진단 개선 (2026-10-19)

- OpenRouter의 모든 HTTP 실패를 502로 덮어쓰던 처리를 수정했습니다. 잔액/키 한도 402와 요청 제한 429를 구분하며, API 키 설정/모델 경로/제공자 오류에는 해당 조치를 안내합니다.
- JSON 파싱 실패, 스키마 불일치, 출력 토큰 소진, 빈 응답, 제공자 응답 제한을 별도 오류로 표시합니다. 실패한 작업에도 안전한 오류 문구/코드를 저장합니다. 외부 오류 본문·비밀 키는 노출하지 않으며 자동 유료 재시도는 추가하지 않았습니다.
- Supabase 배포에서 잘못 보이던 로컬 Firebase Emulator 배너를 숨깁니다.
- 서버/SQL/파서/실행 엔진/모델 오류 처리 테스트 17개 통과. 사용자 신고의 console 502만으로는 실제 서비스 실패 이유를 확정할 수 없어 앱 배너/작업 기록 확인이 필요합니다.

## Cloudflare 로그인 후 조회 오류 수정 (2026-10-19)

- Workers 네이티브 fetch를 Store 객체의 메서드처럼 호출하면서 `Illegal invocation`이 발생하는 문제를 workerd에서 재현했습니다. 기본 전송 함수를 화살표 래퍼로 바꿔 호출 대상을 보존했습니다.
- 실제 workerd 엔진에서 인증 후 `/api/me`, `/api/projects`, `/api/styles`를 실행하는 회귀 테스트를 추가했습니다. 인증/Supabase 응답은 테스트 어댑터이며 실제 배포 계정의 연결 검증과 구분합니다.
- 서버/SQL/파서/런타임 테스트 14개, 타입 검사, Worker dry run 통과. 공개 사이트 직접 요청은 개발 환경의 목적지 정책에 차단되어 공개 배포 후 사용자 세션 확인이 남아 있습니다.
- `keep_vars: true`로 Cloudflare 대시보드의 ALLOWED_EMAILS 등 일반 변수를 재배포 시 보존합니다. Secret 값은 코드에 넣지 않습니다.

## Cloudflare / Supabase 이전 (2026-10-19)

- 정적 Next 화면과 Cloudflare Worker API, Supabase PKCE Google 로그인 및 서버 세션 검증을 추가했습니다. 기존 Firebase Emulator 개발 경로는 보존했습니다.
- Supabase SQL: 계정별 JSON 문서, 서버 전용 권한, 다중 문서 CAS/감사 기록 원자 커밋, 비공개 Storage와 보수적 무료 용량 예약 한도.
- 기획/문체/플롯/집필/부분 수정/버전/내보내기 API를 TypeScript로 이전. 서버 OpenRouter 키, 비용 예약, 미확정 요청 재시도 금지.
- PGlite PostgreSQL의 실제 SQL 함수·권한 검증 및 테스트 어댑터를 통한 전체 흐름·파서 13개 통과. 실제 Supabase 서비스 검증이 아닙니다.
- 정적 빌드, Worker dry run, workerd 로컬 실행, PC/모바일 화면 및 Google OAuth PKCE URL 생성 확인. 실제 Google 로그인 완료는 아직입니다.
- 실제 계정의 SQL 적용/서버 Secret 입력/배포/사용량 측정이 남았습니다. 원본 Firebase 데이터 자동 이관과 전체 v3.1 구현은 포함하지 않습니다.
- [배포 절차 및 무료 플랜 제약](cloud-deployment.md). 큰 파일/ZIP은 Workers Free CPU 한도에서 실패할 수 있습니다.

초기 Emulator 다운로드의 403 차단은 네트워크 설정 변경 뒤 해소됐습니다. 공식 배포 메타의 SHA-256과 파일 크기를 직접 재검증하고 설치·시작·통합 검사를 재실행했습니다. 초기 실패를 현재 실패로 남기지 않고 위 결과로 갱신했습니다.

Google Popup의 초기 `ERR_CERT_AUTHORITY_INVALID` 오류를 조사한 뒤 사용자가 환경 CA 등록을 명시 승인했습니다. 승인된 `/home/agent/.local/share/pki/nssdb`에 시스템 제공 CA를 등록했습니다. 이 Chromium은 기존 `/home/agent/.pki/nssdb`도 사용하며, 제한된 실행 샌드박스에서는 NSS 접근 제한으로 같은 오류가 재현됩니다. NSS에 접근할 수 있는 승인된 실행에서 `node scripts/verify-google-login.cjs`를 수행해 **Google provider 팝업 → Auth Emulator 계정 로그인 → 발급 토큰의 FastAPI 검증 → 대시보드 → 로그아웃**까지 통과했습니다. TLS 검증을 비활성화하지 않았습니다. 이 추가 기능 검사는 기존 39개 검사와 별도로 통과했습니다. 실제 Google 계정/운영 Firebase OAuth 검증을 뜻하지 않습니다.

다운로드·설치에서 TLS·패키지 검증·공식 Emulator 체크섬을 비활성화하지 않았습니다. 차단을 우회해 다른 서버에서 아티팩트를 가져오지 않았습니다.

## 명세와의 차이 / 남은 구현

**실제 사용 전 남은 것:** 사용자 소유 Firebase 프로젝트 연결 후 실제 Google 로그인·모바일 Redirect·계정 A/B/두 기기 클라우드 복원 시험, OpenRouter 실모델의 기획/문체/첫 회차 품질 검수. 로컬 Emulator의 저장·보안·동시 갱신·재시작 복원은 통과했으며 이를 운영 Google Cloud 검증으로 확대 해석하지 않습니다.

초기 저장 구조는 작은 MVP를 위해 11개 기획 모듈과 원문 추적 요약을 프로젝트 문서에 저장합니다. 전체 문서 850KB를 넘는 기획은 거부하며 모듈별 하위 컬렉션 확장은 필요합니다. 원본은 별도 `briefs`/Storage, 원고/장면/버전/검토/프롬프트는 하위 컬렉션입니다. 모든 사용자 콘텐츠 경로는 `/users/{uid}` 아래입니다. Firestore 브라우저 직접 쓰기는 개인 초안도 허용하지 않고 서버 경유로 제한했습니다.

**2차:** 여러 화/시즌/아크/에피소드 운영, 인물·관계·복선·fun_mechanic 독립 엔터티/검색, worldTruth/characterBelief/readerKnown 등의 시점별 기억, 근거 기반 기억 추출, 역색인·OpenRouter 임베딩·Firestore KNN RAG, 5~10화 연속성/영향 그래프, 자동 회귀 검토·롤백, 피드백 기반 문체 개선, 대표 청크 층화/문체 통계·드리프트·정밀 근접복제 검사, 문체 혼합·이름 변경/보관 UI·JSON 재가져오기, DOCX 원고 내보내기, 골든 품질 픽스처/결과 대시보드. 현재 확정 시 캐논 **버전**만 갱신하며 서사 사실을 자동 추출했다고 표시하지 않습니다.

**3차:** Cloud Tasks/Jobs 비공개 Worker, OIDC/IAM 서비스 신원, lease/멱등 실행/중복 과금 방지, 브라우저와 독립된 장편 자동화·안전 중단·재개, STAGED 고아 객체 자동 회수/복구 큐, 관리자 예약 백업·실제 별도 프로젝트 복원, Cloud Billing 실제 비용 연동, 계정/파일/관련 임베딩 완전 삭제와 유예 정책, 대규모 검색 운영.

현재 AI 단계는 동기 HTTP 요청입니다. 완료 응답은 작업 문서에 남지만 브라우저 종료/서버 재시작에도 작업이 계속된다고 보장하지 않습니다. 프롬프트 비교는 원본 JSON 미리보기이며 독립 A/B prompt 실행 비교는 미구현입니다. 노벨피아 기본 글자 수 경고는 제공하지만 플랫폼 규정/AI 게시 허용 여부는 사용자가 확인해야 합니다.

T01~T15 전체 수용 기준은 **아직 통과하지 않았습니다.** 테스트 대역으로 통과한 하위 경로와 실제 서비스에서 필요한 검증을 구분해 운영 승인 여부를 판단해야 합니다.

## 다음 실행 순서

1. 재사용할 설치·시작 지침과 네트워크 도메인이 환경 초안에 저장되어 있습니다. 환경 설정에서 검토·저장한 뒤 준비된 환경을 게시할 수 있습니다. 초안 저장이나 로컬 검증이 게시 완료를 뜻하지는 않습니다.
2. 이후 작업에서는 건강한 실행 인스턴스를 재사용하거나 `bash scripts/dev.sh`로 재시작합니다. 정상 종료 시 Emulator 데이터를 Export하고 다음 실행에서 Import합니다. 새 프로세스에서 이전 UID·원고 revision/해시가 복원되는 것을 검증했습니다.
3. 실제 사용은 Firebase 공개 구성과 GCP 서버 서비스 계정을 연결하고 OpenRouter 서버 비밀 키를 Secret Manager/서버 설정에 등록해야 합니다. 값을 채팅으로 보내지 않습니다.
4. 실제 도메인의 Google 로그인, 실모델 기획/집필, 비용·백업과 계정 격리를 검수한 뒤 게시합니다. 로컬 Google Popup 재검증은 `scripts/verify-google-login.cjs`로 수행하며, Chromium이 NSS 인증서 저장소에 접근할 수 있는 실행 권한이 필요합니다. 환경 CA 등록은 사용자가 승인했고 완료됐습니다.
