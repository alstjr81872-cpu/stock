# Render 공개 웹사이트 배포

이 저장소의 `render.yaml`은 **로그인 없이 누구나 접속할 수 있는 무료 Docker 웹 서비스**를 정의합니다. Render 계정에서 GitHub 저장소에 대한 접근을 연결하고 Blueprint를 생성하면 됩니다. 애플리케이션 방문자는 Render 계정이 필요하지 않습니다.

## 배포 순서

1. Render에 로그인하고 GitHub 계정을 연결합니다.
2. **New → Blueprint**에서 `alstjr81872-cpu/stock` 저장소와 `main` 브랜치를 선택합니다. 파일 경로는 기본값 `render.yaml`입니다.
3. 생성될 `stock-studio` 웹 서비스의 **Free** 플랜을 확인하고 배포를 시작합니다. 설정 이름은 Render UI 변경에 따라 다를 수 있습니다.
4. 빌드·배포가 완료되면 서비스 대시보드에 표시되는 실제 `https://…onrender.com` 주소를 사용합니다. 서비스 이름 중복에 따라 주소가 달라지므로 주소를 미리 가정하지 않습니다.
5. 사이트에서 이미지 업로드와 로컬 업스케일링을 확인합니다. GPT/Gemini 분석을 사용하려는 방문자는 앱 설정에서 **자신의 API 키**를 입력합니다.

저장소가 목록에 보이지 않으면 Render의 GitHub 설치 권한에서 이 저장소 접근을 허용해야 합니다. 저장소의 공개/비공개 여부를 변경할 필요는 없습니다. Render 로그인·배포 작업은 계정 소유자가 진행해야 하며, API 키를 채팅이나 소스에 넣지 마세요.

## 배포 구성

- Docker: Node.js 24, Python, OpenCV, 체크섬 검증된 FSRCNN 모델, React 정적 빌드를 함께 포함합니다.
- Render가 제공하는 `PORT`를 사용하고 `0.0.0.0`에 바인딩합니다.
- 헬스 체크: `/api/health`.
- `PUBLIC_MODE=1`: 방문자별 작업 공간과 공개 서버용 제한 활성화.
- `SESSION_SECRET`: Render Blueprint의 `generateValue: true`로 무작위 생성. 세션 서명과 설정 암호화에 사용합니다. 변경하면 기존 브라우저 작업 공간에 접근할 수 없게 됩니다.
- `RENDER_EXTERNAL_HOSTNAME`: Render가 주입하는 도메인으로 Host를 확인합니다. 별도 도메인을 사용할 경우 `APP_ORIGIN=https://your-domain.example`을 설정하고 코드의 허용 호스트 정책을 해당 도메인에 맞춰 조정하세요.
- `STOCK_DATA_DIR=/app/runtime-data`: 공개 방문자 데이터. 로컬 개발 폴더의 기존 이미지·키는 Docker 이미지에 포함하지 않습니다.

## 방문자 데이터와 무료 플랜

방문자의 임의 세션 ID를 HttpOnly·Secure·SameSite 쿠키에 서명해 저장합니다. 다른 방문자의 이미지 ID를 알아도 그 이미지·메타데이터·원본 다운로드에 접근할 수 없습니다. API 키·FTP 비밀번호는 작업 공간별 AES-256-GCM 암호화 파일에 저장하며, API로 실제 값을 돌려주지 않습니다. 운영자 환경 변수의 AI 키를 방문자가 공용으로 사용하지 못하게 했습니다.

계정 기반의 영구 보관 서비스는 아닙니다. 같은 브라우저의 쿠키를 가진 사용자가 같은 작업 공간에 접근합니다. 미사용 작업 공간은 약 24시간 후 다음 요청 시 정리됩니다. **무료 Render 서비스의 로컬 파일은 재시작·재배포에 따라 삭제될 수 있습니다.** 결과를 다운로드해야 합니다. 파일을 영구 보관하려면 유료 영구 디스크 또는 객체 스토리지와 계정 시스템을 별도로 추가해야 합니다. 이번 설정은 유료 서비스나 유료 디스크를 생성하지 않습니다.

공개 서버 기본 제한:

- 한 번에 5개, 파일당 10MB, 입력 이미지 6MP 이하
- 작업 공간당 20개, 저장 공간 약 100MB까지 (요청 시작 시 확인하므로 진행 중 출력만큼 초과할 수 있음)
- 전체 세션 저장 공간 약 1GB, 최대 500개 작업 공간
- 업스케일 결과 최대 8MP, 무거운 처리는 한 번에 한 요청
- 내보내기·전송은 한 번에 10개
- IP당 분당 120개 요청

무료 플랜은 비활성 시 중지되어 첫 접속이 느릴 수 있으며, 트래픽·메모리·실행시간 제한을 받습니다. 많은 사용자가 동시에 이용하는 운영 환경에는 추가 작업 큐와 외부 스토리지가 필요합니다.

## Render 계정 없이 로컬에서 배포 이미지 확인

```bash
docker build -t stock-studio:render .
# SESSION_SECRET은 32자 이상의 임의 값으로 로컬 환경에서 설정합니다.
docker run --rm -p 10000:10000 \
  -e SESSION_SECRET \
  -e APP_ORIGIN=https://your-test-host.example \
  stock-studio:render
```

공개 모드 쿠키는 HTTPS 전용입니다. 실제 공유 테스트는 HTTPS 프록시를 사용하세요. 로컬 개인용 개발은 기존 `npm run dev`를 사용하면 됩니다.

## 배포 이후 확인

- 실제 발급 URL의 `/api/health`가 HTTP 200을 반환하는지 확인
- 일반 창과 시크릿 창에서 각각 업로드해 이미지가 섞이지 않는지 확인
- 로컬 FSRCNN 업스케일링과 ZIP/XLSX 다운로드 확인
- 사용자 본인의 API 키로 이미지 분석 실행
- 프리픽 실제 전송은 해당 계정의 FTPS 지원·네트워크·권한이 있어야 하며, 심사 제출은 포털에서 별도로 진행
