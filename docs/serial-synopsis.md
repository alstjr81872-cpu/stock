# 10화 단위 시놉시스와 회차별 집필

Cloudflare/Supabase의 STEP 3에서 다음 순서로 진행합니다.

1. **회차당 목표 분량 · 공백 제외**를 설정하고 **분량 저장**을 누릅니다. 범위는 2,000~20,000자입니다.
2. **1~10화 시놉시스 설계**를 눌러 비용을 확인합니다. 회차마다 사건의 원인·선택·결과, 인물 변화, 다음 회차 연결을 제안합니다. **이 구간 기록**으로 저장합니다.
3. **집필할 회차**를 선택합니다. 해당 회차의 시놉시스를 기준으로 장면을 설계하고, 필요하면 **자동 전개**로 누락을 점검·구체화합니다.
4. 플롯을 승인하고 집필실에서 장면별로 원고를 작성합니다. 장면의 목표 글자 수 합계가 회차 목표에 맞게 배분되며, 실제 생성 분량에는 오차가 있을 수 있습니다.
5. 각 회차의 원고를 검토·확정한 뒤 다음 회차로 이어갑니다. 1~10화가 확정되고 현재 회차가 10화이면 **“11화부터 20화까지 시놉시스를 만들까요?”**라고 묻습니다. 나중에 만들기를 선택할 수도 있습니다.
6. 다음 구간을 기록하면 11화로 이동합니다. 이후에도 21~30화, 31~40화 순서로 이어갑니다. 앞 구간의 시놉시스와 확정 원고의 요약·마지막 부분을 참고합니다.

회차 선택으로 기존 원고를 덮어쓰지 않습니다. 장면 플롯은 회차별로 저장·복구하고, 원고·버전·부분 수정 제안도 해당 회차에 귀속됩니다. 다른 탭에서 선택 회차가 바뀌면 오래된 탭의 원고 저장은 충돌로 차단합니다. 새 회차 집필에는 바로 앞 회차의 확정이 필요합니다.

이미 집필한 회차의 목표 분량 변경은 차단합니다. 다음 회차를 선택하고 새 목표를 설정하세요. 더 많은 장면이 필요한 큰 분량으로 변경했다면 플롯을 다시 설계해야 할 수 있습니다. 분량 설정만으로 유료 집필을 자동 실행하지 않습니다.

`synopsis_batches`는 구간별 제안과 확정 기록, `episode_plans`는 각 회차의 장면 설계를 저장합니다. 원고는 `chapters/chapter-N`으로 분리됩니다. 프로젝트 내보내기에 시놉시스와 회차별 플롯이 포함됩니다. 기존 1화 원고와 버전은 보존됩니다. 추가 SQL·키·유료 서비스 설정은 필요하지 않습니다.

자동 테스트는 테스트 모델 응답을 사용합니다. 실제 모델의 장편 연속성·문체·분량 정확도는 실제 작품에서 검수해야 합니다.
